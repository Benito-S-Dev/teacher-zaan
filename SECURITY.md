# Security and privacy

Do not publish production credentials, password hashes, student information, session cookies, database backups or private runtime configuration in issues or pull requests. Reproduce problems with synthetic data.

The public timetable deliberately returns only slot statuses. Teacher routes, reports and history require a server-validated session. Changes to these boundaries need corresponding authorization and privacy tests.

For a suspected vulnerability, use GitHub's private reporting option if enabled on the repository. Otherwise, open a minimal issue requesting a private contact route, without exploit details or private records.
